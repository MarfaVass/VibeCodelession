# Smart Body Academy — VK-бот

Виртуальный администратор сообщества ВКонтакте для **Smart Body Academy («Академия умного тела») Андрея Новикова** (официальный сайт: <https://smartbodyacademy.ru/>).

Бот приветствует пользователя, определяет категорию клиента, отвечает на вопросы по материалам официального сайта Академии (упрощённый RAG с локальной базой знаний) и принимает предварительные заявки, сохраняя их в SQLite.

---

## Назначение проекта

Учебный проект, демонстрирующий практическое применение:

- AI (локальная LLM через Ollama) в роли интеллектуального администратора;
- API ВКонтакте (vkbottle);
- SQLite для хранения заявок;
- упрощённой архитектуры RAG (поиск по локальной базе знаний + формулировка ответа моделью).

## Функциональность

| Возможность | Как работает |
|---|---|
| Приветствие и главное меню | `/start` или первое сообщение: приветствие + кнопки четырёх направлений |
| Определение категории клиента | Ключевые слова Python → при неоднозначности AI-классификатор → при провале один уточняющий вопрос. Кнопки выбора — напрямую |
| Четыре направления | Частный специалист (обучение тренеров), фитнес-клуб/студия, международная организация (в т.ч. на английском), частный клиент (персональные тренировки) |
| Ответы на вопросы | RAG: поиск по разделу базы знаний выбранной категории, модели передаются только найденные фрагменты; нет подтверждённой информации → честный отказ и предложение заявки |
| Предварительная заявка | `/book`: пошаговый сценарий по категории, подтверждение данных, сохранение в SQLite со статусом «предварительное обращение» |
| Отмена | `/cancel` на любом шаге |
| Справка | `/help` |
| Устойчивость | Ollama недоступна / БД недоступна / пустые ответы — бот не падает и объясняет ситуацию |

## Архитектура и структура файлов

```
pilates_vk_bot/
├── bot/
│   ├── main.py            # точка входа: VK-обработчик сообщений (vkbottle)
│   ├── manager.py         # диалоговый менеджер: маршрутизация и сценарии
│   ├── categorize.py      # определение категории клиента (слова + AI-фолбэк)
│   ├── ai_client.py       # клиент Ollama: RAG-запросы, нормализация ошибок
│   ├── keyboards.py       # клавиатуры vkbottle
│   ├── config.py          # настройки из .env
│   ├── prompts/           # system.txt, classify.txt (редактируются без кода)
│   ├── knowledge/
│   │   ├── loader.py      # чтение Markdown-документов с метаданными
│   │   ├── retriever.py   # ключевой поиск по фрагментам (упрощённый RAG)
│   │   └── documents/     # база знаний: specialist/ club/ international/ client/ common/
│   ├── booking/
│   │   └── flow.py        # конечный автомат сценария заявки (4 варианта)
│   └── storage/
│       └── db.py          # SQLite: таблица bookings
├── tests/                 # автотесты (pytest + pytest-asyncio)
├── docs/project_report.md # отчёт о проекте
├── data/bookings.db       # БД (создаётся автоматически, в git не входит)
├── requirements.txt
└── .env                   # секреты (в git не входит)
```

Модель обработки сообщения:

```
VK событие → main.on_message → DialogueManager.handle_message
  ├─ команды/кнопки (/start /menu /book /help /cancel, подтверждение)
  ├─ категория не выбрана → классификация (слова → AI → уточняющий вопрос)
  ├─ категория выбрана → ретривер ищет фрагменты в разделе категории
  │                        → Ollama формулирует краткий ответ по фрагментам
  └─ заявка → BookingFlow (шаги) → подтверждение → SQLite (статус preliminary)
```

## Используемые технологии

- **Python 3.14.8**, виртуальное окружение `.venv`;
- **vkbottle 4.11** — долгий поллинг (long polling), кнопки;
- **python-dotenv** — загрузка `.env`;
- **requests** — HTTP-клиент к Ollama (запускается через `asyncio.to_thread`);
- **SQLite** (модуль `sqlite3`) — заявки;
- **Ollama** с моделью `qwen2.5:3b-32k` (не скачивается заново);
- **pytest + pytest-asyncio** — тесты.

## Требования к запуску

1. Windows/Linux/macOS с Python 3.14 (работает и на 3.12+);
2. Ollama (`https://ollama.com`) с установленной моделью `qwen2.5:3b-32k`;
3. Сообщество ВКонтакте с включёнными **сообщениями сообщества** и ключ доступа **Callback API / Long Polling** с правом «Разрешить доступ к управлению сообществом и отправке сообщений» (`messages`).

## Установка зависимостей

```bash
python -m venv .venv              # если окружения ещё нет
.venv\Scripts\pip install -r requirements.txt   # Windows
.venv/bin/pip install -r requirements.txt       # Linux/macOS
```

## Настройка .env

Файл `.env` в корне проекта (секреты не коммитятся, см. `.gitignore`):

```ini
# Ключ доступа сообщества VK (никогда не публикуется)
VK_TOKEN=vk1.a....
# Локальный Ollama
OLLAMA_URL=http://localhost:11434
# Модель бота
OLLAMA_MODEL=qwen2.5:3b-32k
# Необязательные настройки
DB_PATH=data/bookings.db
AI_TIMEOUT=90
AI_MAX_TOKENS=400
```

## Подключение сообщества VK

1. Открыть настройки сообщества → «Работа с API» → «Ключи доступа»;
2. Создать ключ с областью «Сообщения» (управление сообщениями) — без прав администрирования страниц;

3. Скопировать ключ в `VK_TOKEN` в `.env`;
4. Убедиться, что включены «Возможности ботов» → «Long Polling» (VK API Long Polling используется vkbottle по умолчанию);
5. Запустить `python -m bot.main` — бот начнёт отвечать в личных сообщениях сообщества.

## Настройка Ollama

```bash
ollama serve        # если сервис не запущен
ollama list         # проверка, что qwen2.5:3b-32k установлена
ollama run qwen2.5:3b-32k   # ручная проверка модели (необязательно)
```

Бот и тесты сами проверяют доступность `OLLAMA_URL` и наличие модели (см. `tests/test_ollama_live.py`).

## Запуск бота

```bash
cd pilates_vk_bot
.venv\Scripts\python -m bot.main
```

При запуске бот логирует число загруженных документов базы знаний. Остановка — `Ctrl+C`.

## Команды и сценарии взаимодействия

| Команда / кнопка | Действие |
|---|---|
| `/start`, «Начать» | Приветствие и выбор направления |
| Кнопки направлений («Я хочу стать тренером…», «Я представляю фитнес-клуб или студию», «Я представляю международную организацию», «Меня интересуют персональные тренировки») | Выбор направления без классификации |
| Текстом («хочу стать тренером», «у нас в клубе…», «персональные тренировки…») | Классификация → ответы по материалам Академии |
| `/menu`, кнопка «Другое направление» | Вернуться к выбору направления |
| `/book`, кнопка «Оставить заявку» | Пошаговый сценарий предварительной заявки |
| `/cancel`, «Отменить» | Отмена сценария заявки |
| `/help`, кнопка «Помощь» | Справка |
| Любой вопрос («сколько стоит обучение?») | Ответ из базы знаний выбранного направления; при вопросе во время заявки — ответ AI и продолжение сценария |
| Кнопка «Отправить» / «да» на шаге подтверждения | Сохранение заявки в SQLite |

Заявка содержит: имя, контакт, категорию, суть запроса и категорийные поля (направление/опыт/формат — для специалиста; организация/контактное лицо/сотрудники/программа/пожелания — для клуба; организация/страна/формат мероприятия/тема и сроки — для международных; формат/способ занятий/пожелания — для частных клиентов). Обязательны только имя и контакт.

## Запуск тестов

```bash
.venv\Scripts\python -m pytest
```

Тесты не используют VK-токен и не отправляют сообщения. Живые тесты Ollama и модели (`tests/test_ollama_live.py`) пропускаются, если Ollama не запущена.

## Ограничения проекта

- Ведётся **только предварительная регистрация обращений**: бот не подтверждает записи, не согласовывает время и не обещает места — представитель Академии связывается с пользователем лично.
- Ответы строятся только по собранной базе знаний (снята 2026-11-03); если материала нет — бот честно сообщает это. База не автообновляется: при изменении сайта файлы в `bot/knowledge/documents/` правятся вручную (с полями источник и дата).
- Модель `qwen2.5:3b-32k` — компактная локальная LLM: скорость зависит от железа; возможны периодические неточности формулировок (факты зашиты в ретривер, но полная гарантия «знаний» невозможна).
- Не реализовано: веб-сервер, административная панель, CRM, платежи, календарь, статистика заявок для персонала (все заявки в SQLite доступны напрямую).
- Состояние диалогов хранится в памяти процесса: после перезапуска бот «забывает» незавершённые заявки (подтверждённые заявки сохранены в БД).
- Личная студия Академии на Рублёвском шоссе, расписания групп и актуальные акции фиксируются только на сайте и у представителя.

## Возможные направления развития

- Периодическое обновление базы знаний: скрипт, скачивающий страницы сайта и обновляющий `documents/`;
- Векторный поиск (эмбеддинги) вместо ключевого при росте базы знаний;
- Небольшая админ-панель или выгрузка заявок в CSV/Google Sheets для персонала;
- Смена статуса заявки тренером («обработана») через команды администратора;
- Разделение ответов на «официальные ответы» с цитированием источника (URL) прямо в сообщении;
- Слушатели событий сообщества (подписки, комментарии) через Callback API.

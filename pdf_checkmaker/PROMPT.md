# Промпт, использованный при создании проекта

> **Важно.** Исходный текст промпта, из которого проект был создан, в файлах
> проекта не сохранился. Ниже — **не оригинал**, а восстановленный по итоговой
> реализации составной промпт, подготовленный для документации. Он отражает
> фактическое текущее состояние программы (`pdf_generator.py`, шаблон, README)
> и может отличаться от формулировок исходного запроса.

---

## Восстановленный промпт

Создай консольную программу «PDF-чек-мейкер» на Python в папке проекта
`pdf_checkmaker` внутри репозитория курса вайб-кодинга ОС Windows.

### Что должна делать программа

1. Читать список товаров из CSV-файла `data/products.csv` с колонками
   `product,price,qty` — название товара, цена за единицу, количество. В файле
   должно быть не менее 3–5 реальных записей (бытовая техника и электроника,
   названия на русском).
2. Заполнять данными HTML-шаблон `templates/product_report.html` через Jinja2:
   таблица «Товар / Цена, ₽ / Кол-во / Сумма, ₽», строка-подвал «Итого» с общей
   суммой заказа и дата формирования отчета. Плейсхолдеры в шаблоне —
   `{{ generated_date }}`, цикл `{% for ... in items %}`, `{{ total_sum }}`.
3. Генерировать из этого HTML готовый PDF-файл с помощью WeasyPrint и сохранять
   его в папку `output/product_report.pdf`.
4. После успешной генерации автоматически открывать готовый PDF в стандартной
   программе просмотра документов Windows (ос ОС — Windows, кириллица в PDF
   должна отображаться корректно).
5. Распечатать в консоль понятные сообщения о результатах (путь к файлу,
   количество товаров, ошибки).

### Требования к качеству и обработке ошибок

- Все пути вычислять относительно расположения самого скрипта, чтобы запуск
  работал из любой текущей папки терминала.
- Поддерживать кодировки CSV UTF-8 (в том числе `utf-8-sig`) и Windows-1251.
- Проверять данные и завершаться с кодом 1, выдавая понятное сообщение на
  русском языке, если: CSV не найден или не читается; отсутствуют обязательные
  колонки `product`, `price`, `qty`; название, цена или количество не заполнены
  (с указанием номера строки); цена или количество — не число; цена
  отрицательная; количество не больше нуля; в файле нет ни одной строки
  с данными. Пропускать полностью пустые строки.
- Форматировать суммы по-русски: `1 234,50` (пробел — разделитель тысяч,
  запятая — десятичный разделитель); целые количества печатать без дробной
  части. Длинные названия товаров должны переноситься в таблице PDF.
- Оформить A4-шаблон аккуратно: заголовки, рамки таблицы, выравнивание чисел
  по правому краю, итоговая строка выделена.

### Требования к проектной обвязке

- Создать `requirements.txt` с зависимостями (`jinja2`, `weasyprint`).
- Написать `README.md` на русском: назначение проекта, структура файлов,
  формат входного CSV, установка зависимостей в виртуальное окружение `venv`,
  команда запуска на Windows и расположение готового PDF. Отдельным разделом
  описать особенность WeasyPrint на Windows: нужны системные библиотеки
  GTK/Pango, которые не ставятся через pip (MSYS2: `pacman -S
  mingw-w64-ucrt-x86_64-pango` и добавление `C:\msys64\ucrt64\bin` в PATH,
  либо GTK3 runtime installer).
- Добавить папку `output/` с файлом `.gitkeep`; не коммитить лишние артефакты.
- Программа должна работать только на стандартной библиотеке Python плюс
  `jinja2` и `weasyprint`, без дополнительных утилит командной строки.

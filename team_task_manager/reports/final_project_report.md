# Итоговый отчет о домашней работе — TEAM TASK MANAGER

*Дата: 21.11.2026. Проект: Telegram-бот ведения задач команды.*

---

## 1. Название и назначение проекта

**TEAM TASK MANAGER** — Telegram-бот для сбора, хранения, распределения и
контроля выполнения задач одной команды/организации. Бизнес-специфика
(категории, статусы, приоритеты, состав команды) настраивается
администратором через интерфейс и не зашита в код.

## 2. Цели и задачи

Цели из исходного ТЗ (`Промпт.docx`, извлечённый текст — `prompt_extracted.txt`):

- создать полноценного Telegram Task Manager на Python/aiogram 3.x/SQLite;
- обязательные команды учебного задания: `/start`, `/add`, `/list`, `/list_csv`;
- расширения: `/my`, `/stats`, `/export_excel`, `/help`;
- роли ADMIN/MEMBER, настраиваемые справочники, уведомления,
  экспорт CSV/XLSX, логирование, резервное копирование, миграции;
- автоматические тесты, документация, пошаговая разработка по этапам.

| Просмотр | списки «все»/«мои», фильтры (статус/категория/приоритет/просроченные/выполненные), Unicode-поиск по кириллице, пагинация 10/страницу, `/list` от старых к новым |

| Экспорт | CSV (UTF-8 BOM, «;») и XLSX (3 листа: ЗАДАЧИ/СВОДКА/СПРАВОЧНИКИ) — командами и кнопками из меню; отправка документом Telegram с именем `tasks_ГГГГ-ММ-ДД_ЧЧ-ММ`; временные файлы удаляются (в т.ч. при ошибке); пустая база — пустой отчёт |

| Навигация | «⬅️ К списку» из карточки сохраняет фильтр и страницу; «🏠 Главное меню» из любого экрана; управляемая отмена незавершённых FSM-сценариев с уведомлением; поиск переживает возврат в меню |
| Инфраструктура | `.env`-конфигурация, ротация логов, backup API, миграции v1, меню команд бота при старте |

## 4. Архитектура и технологии

- Python 3.12.10; aiogram 3.32; SQLite (aiosqlite); openpyxl; python-dotenv; tzdata.
- Слои: `handlers` (восемь роутеров) → `services` (бизнес-правила) →
  `repositories` (SQL) → `database` (aiosqlite-обёртка, транзакции);
  `keyboards`, `states`, `middlewares`, `exports`, `utils`, `config`.
- SQLite — единственный источник истины (двусторонней синхронизации с
  Excel нет по ограничению ТЗ). PostgreSQL, Docker, веб-панель, Google
  Sheets не используются.

## 5. Роли и права доступа

| Действие | ADMIN | MEMBER |
|---|---|---|
| Просмотр задач | все | все активные |
| Создание задач | да | да |
| Редактирование своей назначенной задачи | да | да |
| Чужие задачи (правка/статус) | да | нет |
| Удаление | да | нет |
| Справочники, участники | да | нет |

Проверки — серверная сторона (`TaskService.can_*` + `AccessControlMiddleware`).
ROLE MEMBER с неактивным статусом теряет доступ немедленно. Первый админ —
из `ADMIN_IDS`.

## 6. База данных

SQLite, 8 таблиц: `users`, `categories`, `statuses` (`is_final`,
`sort_order`), `priorities`, `tasks` (даты: `created_at`, `updated_at`,
`due_date`, `completed_at`), `task_history`, `settings`, `notifications`.
Внешние ключи, WAL, транзакции `Database.transaction()`, индексы для частых
запросов, версионирование схемы (миграция v1 создаёт всё). UTC-хранение,
отображение через `TIMEZONE` (в текущей конфигурации Asia/Moscow).

## 7. Дополнительные улучшения (впоследствии принятых этапов)

- **Этап 1 — экспорт через меню**: кнопки «📄 Скачать CSV»/«📊 Скачать Excel»
  (`exp:csv`/`exp:xlsx`), единый helper `_build_and_send`, нейтральные
  каптионы, обработка ошибок отправки, пустая база отдаёт пустой отчёт.
- **Этап 2 — навигация**: управляемая очистка FSM (`leave_scenario` —
  сохраняются только `last_list`/`search_text`), контекст списков,
  футеры «Назад»/«К карточке»/«Главное меню», тупики админ-справочников.
- Меню команд бота (`set_my_commands`, 8 команд) при старте.
- Unicode-поиск по кириллице через SQL-функцию `ufold()` (casefold),
  фильтрация в SQL до пагинации.
- Латентные исправления: tz-aware datetime в openpyxl (экспорт Excel),
  `PatternFill` для цветовых индикаций, перечитка пользователя в
  `ensure_registered` (первый контакт), корректный класс исключения в
  тесте транзакции.

## 8. Исправленные ошибки (в ходе проекта)

1. `Database.transaction()` — `async def` не совпадает с использованием
   `async with`; блокировал все тесты.
2. Отсутствие `tzdata` на Windows — падение `zoneinfo`.
3. Вебхук Salebot на токене — блокировал polling (устранён по согласованию).
4. `ensure_registered` возвращал `None` при первой регистрации — падение
   `/start` у нового участника (живая ошибка, исправлена с тестами).
5. Пустое меню команд бота — реализован `set_my_commands`.
6. Поиск кириллицы в смешанном регистре — `ufold()`.
7. XLSX-экспорт падал на timezone-aware datetime — `_local_naive()`.
8. Цветовые заливки Excel не применялись (строка вместо `PatternFill`).

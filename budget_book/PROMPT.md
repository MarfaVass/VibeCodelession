# PROMPT.md — исходное задание (история)

Ты — senior Python-разработчик. В текущей родительской папке создай новую папку проекта budget_book и реализуй в ней CLI-приложение «Книга доходов и расходов» на Python 3.10+. Все файлы создавай сам внутри budget_book/, не выходи за её пределы. В конце прогони проверку.

Шаг 0. Создай структуру проекта:

```
budget_book/
  data/
  main.py
  storage.py
  models.py
  validators.py
  reports.py
  charts.py
  demo.py
  smoke_test.py
  requirements.txt
  README.md
  .gitignore
  PROMPT.md
```

Если папка budget_book уже существует — не удаляй её, работай внутри, аккуратно дополняя.

Цель приложения: пользователь ведёт план и факт доходов и расходов за месяц, видит план-факт по категориям и две диаграммы.

Функционал (все пункты обязательны):

1. Хранение данных в JSON-файле data/budget.json (путь относительно budget_book/). При первом запуске файл создаётся автоматически. Если файл повреждён — приложение не падает, а сообщает об ошибке и создаёт новый.
2. Плановые доходы: источник + сумма.
3. Плановые расходы двух типов: mandatory (обязательные платежи) и purchases (плановые покупки). У каждого: категория, название, сумма.
4. Фактические доходы и расходы: категория (для расходов), название, сумма, дата (ставится автоматически).
5. Отчёт «План-факт»:
   - итоги по доходам (план / факт);
   - итоги по расходам (план / факт), отдельно mandatory и purchases;
   - остаток (план / факт);
   - таблица по категориям: план, факт, процент выполнения плана (если план 0 — прочерк, без деления на ноль).
6. Диаграммы через matplotlib:
   - plan_vs_fact.png — столбчатая, план vs факт по категориям;
   - actual_expenses.png — круговая, структура фактических расходов;
   - если фактических расходов нет — круговую не строить, вывести сообщение;
   - сохранять картинки в budget_book/ (корень проекта).
7. Меню-цикл: пункты «добавить план/факт», «показать отчёт», «построить диаграммы», «выход».

Требования к качеству:

- Валидация ввода: нечисловой ввод, отрицательные суммы, пустые строки, запятая вместо точки (99,50 → 99.50). При ошибке — понятное сообщение и повторный запрос.
- Обработка Ctrl+C — корректный выход без трейсбека.
- Код разбит на модули:
  - main.py — точка входа и меню;
  - storage.py — загрузка/сохранение JSON, обработка повреждённого файла;
  - models.py — структуры данных (dict-хелперы или dataclass);
  - validators.py — функции валидации ввода;
  - reports.py — расчёт план-факта и вывод таблицы;
  - charts.py — построение диаграмм;
  - demo.py — заполняет data/budget.json демо-данными (зарплата 80000, аренда 30000, продукты 20000 и несколько фактических трат), чтобы можно было сразу увидеть работу.
- Функции с docstring, имена переменных читаемые, никаких «магических» чисел без констант.
- Никаких внешних API, БД и токенов. Только стандартная библиотека + matplotlib.

Обязательные файлы:

- requirements.txt с зафиксированной зависимостью matplotlib;
- README.md: описание, установка (pip install -r requirements.txt), запуск (python main.py), сценарий демо (python demo.py), пример вывода отчёта, структура проекта, известные ограничения, раздел «Решения, принятые при разработке»;
- .gitignore: venv/, __pycache__/, *.pyc, data/budget.json, *.png, .vscode/;
- PROMPT.md — вставь сюда этот промпт (для истории).

Порядок работы:

1. Создай папку budget_book/ и внутри неё — всю структуру.
2. Наполни файлы кодом.
3. Создай requirements.txt, README.md, .gitignore, PROMPT.md, demo.py.
4. Перейди в budget_book/ и установи зависимости: pip install -r requirements.txt.
5. Прогони python demo.py — убедись, что data/budget.json создан.
6. Напиши smoke_test.py, который импортирует функции из reports.py и charts.py, прогоняет их на демо-данных и печатает «OK», если всё отработало без исключений. Запусти python smoke_test.py.
7. Если тест упал — исправь и повтори п.6.

В конце выведи: полный путь к созданной папке budget_book, список созданных файлов, результат smoke-теста и одну команду ручного запуска (из budget_book/).

Не задавай мне уточняющих вопросов — принимай разумные решения сам и фиксируй их в README в разделе «Решения, принятые при разработке».

## Дополнение (второй промпт): справочник расходных категорий (обязательно)

Помимо уже описанного функционала, добавь в проект справочник категорий расходов:

1. Новый модуль categories.py и файл данных data/categories.json. При первом запуске data/categories.json создаётся автоматически из дефолтного списка, зашитого в categories.py:
   ["Жильё", "Продукты", "Транспорт", "Здоровье", "Образование", "Развлечения", "Одежда", "Связь и интернет", "Подписки", "Подарки", "Прочее"].
   Если categories.json повреждён — не падать, восстанавливать из дефолта и сообщать пользователю.
2. Ввод категории только выбором из списка. При добавлении планового расхода (mandatory или purchases) и фактического расхода пользователь не пишет категорию текстом, а выбирает её по номеру из выведенного пронумерованного списка. При неверном номере — повторный запрос с подсказкой. Функция выбора — в validators.py или categories.py, как решишь по структуре, но с docstring.
3. Управление категориями в меню. Добавь отдельный пункт меню «Управление категориями» с двумя действиями: показать список с номерами и добавить новую категорию. Дубликаты (без учёта регистра и с обрезкой пробелов) не добавляются — выводится сообщение «Такая категория уже есть».
4. Порядок в отчёте и на диаграммах — как в справочнике, а не по алфавиту. В таблице план-факта и в обеих диаграммах категории идут в порядке data/categories.json. Категории без плана и без факта в таблицу не выводятся.
5. Фиксированные цвета категорий. В charts.py сделай палитру цветов по индексу категории в справочнике и используй её и для столбчатой, и для круговой диаграммы, чтобы одна и та же категория всегда была одного цвета.
6. demo.py должен заполнить демо-данные по разным категориям (например, Жильё, Продукты, Транспорт, Развлечения), чтобы сразу было видно и таблицу с несколькими строками, и разные цвета на круговой.
7. smoke_test.py дополнительно проверяет: выбор категории по номеру, добавление новой категории, отказ на дубликат без учёта регистра.
8. .gitignore: файл data/categories.json не игнорировать — справочник должен попадать в репозиторий как стартовый. Игнорировать только data/budget.json, *.png, venv/, __pycache__/, *.pyc, .vscode/.
9. README.md: добавь раздел «Справочник категорий» — какие категории стартовые и как добавить свою.
10. В финальном выводе после прогона smoke_test.py покажи текущий список категорий из data/categories.json с номерами.

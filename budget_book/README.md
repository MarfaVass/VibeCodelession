# Книга доходов и расходов (budget_book)

Локальное веб-приложение на Streamlit (Python 3.10+): ведение плана и факта
расходов по месяцам, отчёт «план-факт» по статьям и две диаграммы
(matplotlib). Данные — в JSON, внешних API и баз нет. Предыдущая CLI-версия
сохранена в git-истории (коммит `4182686`), история изменений — в REPORT.md.

## Возможности

- **Выбор месяца** над вкладками — применяется к плану, фактам и отчёту;
  месяцы хранятся отдельно в `data/budget.json`.
- **Вкладка «План»**:
  - плановые доходы: источник + сумма (месяц и год берётся из селектора);
  - шаблонные статьи расходов (жильё, коммунальные, продукты, транспорт
    и т. д.) с полем суммы для каждой — план месяца заполняется прямо
    в списке; ноль = статья без плана;
  - добавление новой статьи — она сразу появляется в списке шаблонных
    и сохраняется в справочнике для последующих месяцев.
- **Вкладка «Факт»**: фактический расход — сумма, дата, статья
  (только из справочника), комментарий; список трат месяца
  с кнопками удаления.
- **Вкладка «Отчёт»**: сводка (план доходов, план/факт расходов, остаток),
  таблица по статьям (план, факт, разница, процент от плана — при нулевом
  плане прочерк `—`) и две диаграммы:
  - `plan_vs_fact.png` — план vs факт по статьям (план светлее, факт
    насыщеннее, цвет статьи фиксированный по справочнику);
  - `actual_expenses.png` — структура фактических расходов (не строится,
    если трат за месяц нет).
- **Валидация**: суммы неотрицательные (Streamlit `number_input` с нижней
  границей 0), ноль и пустые поля не сохраняются (понятные сообщения),
  дубликаты статей (без учёта регистра и внешних пробелов) не добавляются.

## Установка

```bash
pip install -r requirements.txt
```

## Запуск

```bash
streamlit run app.py
```

Браузер откроется на http://localhost:8501 автоматически.

## Демо

```bash
python demo.py
streamlit run app.py
```

`demo.py` перезаписывает `data/budget.json` готовым примером текущего
месяца: план доходов — зарплата 80 000 и подработка 20 000; план статей —
жильё 36 000, продукты 20 000, транспорт 3 000, здоровье 4 000,
развлечения 5 000, одежда 12 000; плюс фактические траты (аренда,
вторая закупка и т. д.). Предыдущий месяц при желании заполните сами —
данные не пересекаются между месяцами.

```text

Факт расходов: 56 700,00   Остаток план: 20 000,00

План-факт по статьям:
  Статья      |       План |       Факт |     Разница | % от плана
  Жильё       | 36 000,00  | 35 200,00  |   800,00    |    97.8%
  Продукты    | 20 000,00  | 15 300,00  |  4 700,00   |    76.5%
  Транспорт   |  3 000,00  |  3 000,00  |      0,00   |   100.0%
  Здоровье    |  4 000,00  |  1 800,00  |  2 200,00   |    45.0%
  Развлечения |  5 000,00  |  1 400,00  |  3 600,00   |    28.0%
```

Диаграммы сохраняются в корне проекта (`plan_vs_fact.png`,
`actual_expenses.png`) и одновременно показываются на вкладке «Отчёт».

## Известные ограничения

- Суммы записываются float с округлением до копеек; для банковских
  расчётов уместнее `Decimal`.
- Плановый доход не имеет собственной даты: месяц задаётся селектором
  (записано в «Решениях»).
- В fact-расходе дата может принадлежать любому месяцу — запись уходит
  в свой месяц, но селектор «Факт» показывает только текущий;
  чтобы увидеть трату, переключите месяц.
- Фактических доходов (поступлений) в интерфейсе нет — «Остаток факт»
  считается только по расходам.
- Статьи из старых данных, отсутствующие в справочнике, рисуются серым
  и печатаются в конце таблицы.
- Streamlit-интерфейс не покрыт автотестами — проверено вручную,
  см. REPORT.md.

## Решения, принятые при разработке

1. **Streamlit вместо ручного HTML/CSS** — рекомендации задания: вкладки,
   формы и кнопки из коробки; страница остаётся одним модулем app.py.
2. **Данные переехали на структуру по месяцам** (`{"months": {...}}`):
   селектор месяца должен показывать независимо ведущиеся месяцы.
   Устаревший CLI-формат (план/факт в корне файла) автоматически
   мигрируется при первом запуске: обязательный платежи/покупки сливаются
   в статьи по совпадению категорий, «name» расхода становится комментарием.
3. **Одна сумма на статью в месяце** (`models.set_planned_article`
   заменяет прежнюю) вместо накопления: список шаблонных статей
   с полями — это «редактирование плана месяца», а не лента записей;
   ноль убирает статью.
4. **Месяц планового дохода — селектор** (месяц и год), отдельное поле
   даты не нужно; факт-расход, наоборот, хранит полную дату — её даёт
   поле даты.
5. **Комментарий обязателен** — «пустые поля не сохраняются» применено
   и к статье, и к сумме, и к комментарию фактического расхода; сумма
   строго больше нуля (ноль = незаполненное поле), но отрицательные
   значения невозможны даже синтаксически (number_input с min_value=0).
6. **Факт-доходы убраны из интерфейса**, поскольку задание описывает
   ввод только расходов; миграция старых факт-доходов опущена ради
   честной статистики, а не смешанной ленты. Отчёт по доходу показывает
   только план; остаток факт считается по расходам.
7. **Цвет статьи привязан к индексу справочника** — одна статья всегда
   одного цвета на обеих диаграммах, порядок строк и секторов — порядок
   справочника; палитра прогнана через CVD-валидатор (OKlab ΔE ≥ 8).
8. **PNG-файлы пересоздаются на каждый Показ**, а Streamlit только
   отображает их (`st.image`) — диаграммы остаются доступными
   и вне вкладки отчёта, как в CLI-версии.
9. **Smoke-тест не трогает пользовательские данные**: демо-и справочники
   тестируются во временной папке; PNG строятся туда же. Streamlit-часть
   автотестами не покрыта — так решили заранее (см. REPORT.md).

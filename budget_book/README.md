# Книга доходов и расходов (budget_book)

CLI-приложение на Python 3.10+: ведение плана и факта доходов и расходов
за месяц, отчёт «План-факт» по категориям и две диаграммы (PNG через
matplotlib). Внешних API, баз данных и токенов нет — только стандартная
библиотека и matplotlib.

## Возможности

- Плановые доходы: источник + сумма.
- Плановые расходы двух типов: `mandatory` (обязательные платежи) и
  `purchases` (плановые покупки), у каждого — категория (выбором из
  справочника), название, сумма.
- Фактические доходы и расходы: категория (выбором из справочника),
  название, сумма, дата ставится автоматически в момент ввода.
- Отчёт «План-факт»: итоги по доходам, расходам (отдельно mandatory и
  purchases), остатку и таблицы по категориям с процентом выполнения плана
  (при нулевом плане — прочерк `—`, без деления на ноль). Расходные
  категории идут в порядке справочника; без плана и без факта не печатаются.
- Диаграммы в корне проекта:
  - `plan_vs_fact.png` — столбчатая, план vs факт по категориям (план —
    светлее, факт — насыщеннее; цвет категории фиксированный по справочнику);
  - `actual_expenses.png` — круговая, структура фактических расходов
    (не строится, если фактических трат ещё нет).
- Справочник категорий `data/categories.json` (см. раздел ниже).
- Валидация ввода: нечисловой ввод, ноль и отрицательные суммы, пустые
  строки, запятая вместо точки (`99,50 → 99.50`); при ошибке — сообщение и
  повторный запрос.
- Ctrl+C и Ctrl+D (EOF) завершают приложение без трейсбека.

## Установка

```bash
pip install -r requirements.txt
```

## Запуск

```bash
python main.py
```

Файл `data/budget.json` создаётся автоматически при первом запуске.

## Демо

```bash
python demo.py
python main.py
```

`demo.py` перезаписывает `data/budget.json` готовым примером: план —
зарплата 80 000, подработка 20 000; обязательные платежи — аренда 30 000,
коммунальные 6 000, продукты 20 000, транспорт 3 000, здоровье 4 000;
покупки — билеты в театр 5 000 (Развлечения), куртка 12 000 (Одежда);
плюс несколько фактических трат с разными датами.
Далее пункты меню: `[3]` — отчёт, `[4]` — диаграммы, `[5]` — управление
категориями, `[0]` — выход.

## Справочник категорий

Расходные категории теперь не свободный текст, а справочник
`data/categories.json`. При первом запуске он создаётся автоматически
из дефолтного списка:

```text
1. Жильё    4. Здоровье      7. Одежда         10. Подарки
2. Продукты 5. Образование   8. Связь и интернет 11. Прочее
3. Транспорт 6. Развлечения  9. Подписки
```

- При добавлении планового и фактического расхода категория выбирается
  **по номеру** из напечатанного списка; неверный номер — повторный запрос
  с подсказкой.
- В меню есть пункт `[5]` «Управление категориями»: `[1]` показать список,
  `[2]` добавить категорию. Дубликаты (без учёта регистра и внешних
  пробелов) не добавляются — печатается «Такая категория уже есть».
- Файл `data/categories.json` **не игнорируется** в .gitignore — стартовый
  справочник попадает в репозиторий. Повреждённый файл восстанавливается
  из дефолтного списка (испорченная копия сохраняется рядом).
- Порядок категорий в справочнике задаёт порядок строк в таблице отчёта
  и секторов на диаграммах; цвет категории тоже привязан к её номеру
  в справочнике — категория всегда одного цвета на обеих диаграммах.

## Известные ограничения

- Ведётся один месяц: файл данных не разделяет записи по месяцам
  (принято как упрощение — «сброс» выполняется запуском `demo.py`
  или очисткой файла).
- Суммы — float с округлением до копеек; для банковских расчётов
  стоило бы использовать `Decimal`.
- Дата факта ставится автоматически, задать «задним числом» нельзя.
- Плановые записи нельзя редактировать/удалять из меню (только
  вручную в файле при не запущенном приложении).
- Фактический расход не помечен как mandatory/purchases: тип
  восстанавливается по совпадению категории с плановой, иначе
  запись попадает в «Прочие».
- Расходная категория обязательно берётся из справочника: записи
  с категориями, добавленными в `budget.json` вручную и не попавшими
  в «Управление категориями», попадают в «Прочие» и рисуются серым.
- Круговая диаграмма показывает не более 11 секторов (по числу
  категорий палитры): лишние мелкие категории сворачиваются в «Прочее».

## Решения, принятые при разработке

1. **Один JSON-файл со всей структурой** вместо отдельных файлов по типам
   записей: месячный бюджет атомарен, запись одной командой исключает
   рассинхронизацию, а структура документирована константами в `models.py`.
2. **Повреждённый файл не затирается молча**: копия переносится в
   `data/budget.corrupt.json`, а приложение начинает с нового пустого
   бюджета и печатает предупреждение. Так ничего не теряется безвозвратно.
3. **Сумма — строго дробное число > 0**: ноль и отрицательные значения
   отвергаются, потому что «план ноль» выражается отсутствием записи,
   а не нулём; округление до двух знаков происходит сразу.
4. **Запятая и пробелы — допустимые символы ввода**: `99,50`, `1 500`
   нормализуются, чтобы не наказывать привычный русскоязычный ввод.
5. **Тип фактического расхода (mandatory/purchases) восстанавливается по
   категории плана**; совпадения нет — запись попадает в «Прочие»
   (план 0, процент — прочерк). Это проще, чем хранить тип в каждой трате,
   и сохраняет разрез итогов.
6. **Стратегия пустых данных**: отчёт честно печатает `(нет данных)`,
   а круговая диаграмма при отсутствии факта не строится и сообщается —
   пустые картинки в проект не сваливаются.
7. **matplotlib в режиме `Agg`** — приложение не требует GUI-бэкенда
   и работает по SSH/в скриптах; диаграммы только сохраняются в PNG.
8. **Smoke-тест не портит пользовательские данные**: если
   `data/budget.json` заполнен, тест гоняется на нём, иначе — на
   демо-данных в памяти без записи на диск.
9. **Категория расхода — только выбором из справочника**, свободный текст
   отключён: это гарантирует совпадение написания между планом и фактом,
   поэтому разрез mandatory/purchases и цвета работают без ручной сверки
   правописания.
10. **Цвет категории привязан к индексу в справочнике** — одна и та же
    категория всегда одного цвета на столбчатой и круговой диаграммах.
    План рисуется тем же цветом с прозрачностью, факт — насыщенно;
    до категории — нейтральный серый (в его цвет «крадётся» смысл).
    Добавленные пользователем категории после 11-й получают цвет
    по остатку от деления индекса на длину палитры.
11. **Порядок категорий — из справочника, а не по алфавиту**, чтобы отчёт
    и диаграммы выглядели стабильно независимо от набора записей;
    категории без плана и без факта в таблицу не выводятся.
12. **Палитра проверена скриптом на совместимость с дальтонизмом**
    (CVD-валидатор по OKlab): 11 оттенков проходят порог CVD ΔE ≥ 8
    и нормального зрения; сектора и столбцы разделены зазорами, а мелкие
    проценты не печатаются, чтобы подписи не наезжали друг на друга.
13. **Файл `data/categories.json` не игнорируется в .gitignore** — стартовый
    справочник попадает в репозиторий, в отличие от пользовательских
    `data/budget.json` и `*.png`.

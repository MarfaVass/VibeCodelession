# Книга доходов и расходов (budget_book)

Локальное веб-приложение на Streamlit (Python 3.10+): ведение плана и факта
расходов по месяцам, отчёт «план-факт» по группам и подкатегориям, две
диаграммы (matplotlib), справочник категорий в два уровня. Данные — в JSON,
внешних API и баз нет. История версий (CLI → Streamlit → двухуровневые
категории) — в REPORT.md.

## Возможности

- **Выбор месяца** над вкладками — применяется к плану, фактам и отчёту;
  месяцы хранятся отдельно в `data/budget.json`.
- **Деньги «на виду»**: во вкладке «План» — входящий остаток (редактируемое
  поле) + плановый доход + план расходов + «свободно»; перерасход плана
  подсвечивается сразу. Во вкладке «Факт» — та же сводка сверху, но
  с фактом трат: остаток «доход − расход» виден при заполнении.
- **Вкладка «План»**:
  - плановый доход: быстрый разрез «Зарплата / Подработка / Прочий доход»
    (полями на странице) и произвольные источники через диалог;
  - шаблонный статьи плана — по подкатегориям, сгруппированные по группам:
    заголовок «Жильё», под ним поля для «Аренды», «Коммуналки» и т. д.;
    ноль = статья без плана;
  - добавление группы или подкатегории — сразу появляется в справочнике
    и в шаблонном списке.
- **Вкладка «Факт»**: расход — сумма, дата, группа → подкатегория
  (зависимые выпадающие списки), комментарий; список трат месяца
  с кнопками удаления.
- **Вкладка «Отчёт»**: сводка, компактная таблица по группам
  (план, факт, разница, процент от плана — при нулевом плане прочерк `—`),
  план-факт по группам с раскрытием подкатегорий (раскрытие через
  expander: «Жильё: план 36 000, факт 39 000» и внутри строки по
  подкатегориям) и две диаграммы на уровне групп:
  - `plan_vs_fact.png` — план vs факт по группам (план светлее, факт
    насыщеннее, цвет группы фиксированный по справочнику);
  - `actual_expenses.png` — структура фактических расходов по группам
    (не строится, если трат за месяц нет).
- **Вкладка «Категории»**: справочник с номерами групп, добавление
  группы (сразу с подкатегориями или пустой), добавление подкатегории,
  удаление группы или подкатегории (записи, ссылающиеся на статью,
  переносятся в «Прочее» — см. REPORT.md).

## Справочник категорий (два уровня)

`data/categories.json` — словарь «группа → список подкатегорий».
При первом запуске создаётся из дефолтного списка:

```text
Жильё:        Аренда, Коммунальные услуги, Ремонт, Работники, Участок
Здоровье:     Аптека, Врачи, Анализы, Страховка
Одежда:       Верхняя одежда, Обувь, Аксессуары
Развлечения:  Кино, Кафе, Хобби, Подписки
Обучение:     Курсы, Книги, Репетиторы
Связь:        Мобильная связь, Интернет
Транспорт:    Общественный, Такси, Топливо, Ремонт авто
Путешествия:  Билеты, Отели, Экскурсии
Прочее:       Подарки, Непредвиденное
```

- Дубликаты (без учёта регистра и внешних пробелов) не добавляются.
- Порядок групп задаёт порядок строк отчёта/секторов и цвет группы
  на обеих диаграммах.
- Файл **не игнорируется** в `.gitignore` — стартовый справочник в репо.
- Повреждённый или старый плоский файл мигрируется/восстанавливается
  из дефолта (копия сохраняется рядом).

## Установка

```bash
pip install -r requirements.txt
```

## Запуск

```bash
streamlit run app.py
```

## Демо

```bash
python demo.py
streamlit run app.py
```

`demo.py` перезаписывает `data/budget.json` готовым примером текущего
месяца: входящий остаток 15 400; план доходов — зарплата 80 000,
подработка 20 000, прочий доход 5 000; план статей — аренда 30 000,
коммунальные 6 000, топливо 8 000, общественный 1 500, аптека 4 000,
кино 3 000, кафе 4 000, верхняя одежда 12 000; плюс фактические траты
по тем же (и нескольким другим) подкатегориям.

## Структура проекта

```text
budget_book/
  data/                 # budget.json — данные по месяцам (в .gitignore);
                        # categories.json — справочник (в репо)
  app.py                # точка входа Streamlit (streamlit run app.py)
  storage.py            # загрузка/сохранение JSON, миграции форматов, ремонт файла
  categories.py         # двухуровневый справочник: файл, CRUD, дубликаты
  models.py             # структура бюджета по месяцам, конструкторы, миграции
  validators.py         # валидация сумм и текстов (чистые функции)
  reports.py            # план-факт по группам/подкатегориям, итоги, текстовый отчёт
  charts.py             # диаграммы matplotlib по группам (PNG)
  demo.py               # демо-данные для быстрого знакомства
  smoke_test.py         # автопроверка логики (не Streamlit-части) — см. REPORT.md
  REPORT.md             # история изменений: CLI → Streamlit → категории
  requirements.txt      # зависимости (streamlit, matplotlib — зафиксированы)
  PROMPT.md             # промпты задания (история)
  README.md
  .gitignore
```

## Известные ограничения

- Суммы — float с округлением до копеек; для банковских расчётов
  уместнее `Decimal`.
- Входящий остаток — редактируемое поле, не вычисляется автоматически
  из фактов прошлых месяцев (факт-доходов в интерфейсе нет).
- Записи с подкатегориями, удалёнными/не встречающимися в справочнике,
  печатаются в конце своей группы (по алфавиту) и рисуются серым.
- Факт-доходов (поступлений) в интерфейсе нет: «свободно» считается как
  входящий остаток + плановый доход − расходы.
- Дата расхода может принадлежать любому месяцу — запись уходит в свой
  месяц; чтобы её видеть, переключите селектор.
- Streamlit-интерфейс не покрыт автотестами — проверено вручную,
  см. REPORT.md.

## Решения, принятые при разработке

1. **Streamlit вместо ручного HTML/CSS** — рекомендации задания: вкладки,
   формы и кнопки из коробки; страница остаётся одним модулем app.py.
2. **Данные хранятся по месяцам** (`{"months": {...}}`): селектор месяца
   показывает независимо ведущиеся месяцы; старые форматы (CLI и
   плоский Streamlit-v2) мигрируются автоматически при загрузке.
3. **План — редактирование списка, а не лента записей**: плановая сумма
   подкатегории одна (`models.set_planned_article` заменяет); ноль
   убирает статью из плана.
4. **Месяц планового дохода — селектор** (месяц и год), отдельного поля
   даты нет; факт-расход хранит полную дату.
5. **Сумма строго > 0 для сохранения** (ноль = «поле пустое»), но
   отрицательные значения невозможны даже синтаксически
   (`number_input(min_value=0)`); комментарий обязателен — «пустые
   поля не сохраняются».
6. **Факт-доходов в интерфейсе нет** (задание описывает ввод только
   расходов); сводка использует плановый доход — и этого достаточно,
   чтобы видеть «доход − расход» при заполнении.
7. **Входящий остаток — ручное поле месяца**: точнее вычисления из
   фактов невозможно без факт-доходов; допускает отрицательное значение.
8. **Цвет группы привязан к индексу справочника** — одна группа всегда
   одного цвета на обеих диаграммах; подкатегории на диаграммах не
   рисуются (их разрез показывает таблица отчёта). Палитра прогнана
   через CVD-валидатор (OKlab ΔE ≥ 8).
9. **Порядок в отчёте — порядок справочника**, статьи без плана и без
   факта не выводятся.
10. **PNG пересоздаются при показе отчёта** и доступны вне вкладки —
    как в CLI-версии.
11. **Smoke-тест не трогает пользовательские данные**: демо, справочник
    и диаграммы тестируются во временной папке. Streamlit-часть
    автотестами не покрыта — преднамеренное решение (см. REPORT.md).

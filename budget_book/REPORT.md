# REPORT.md — отчёт по домашнему заданию budget_book

Приложение «Книга доходов и расходов»: локальный сайт на Streamlit для
планирования и учёта расходов по месяцам. Версии (всё в git-истории):

| Версия | Коммит | Что это |
|---|---|---|
| v1 CLI | `4182686` | Консольное меню, плоские категории |
| v2 Streamlit | `db6330d` | Локальный сайт: месяц, вкладки, диаграммы |
| v3 двухуровневые категории | `5728e01` | Группы → подкатегории, деньги «на виду» |

CLI-версия — первая, веб — вторая итерация по запросу пользователя
(«переделай из консольного в веб-приложение, Streamlit»), двухуровневые
категории — третья итерация. Ниже — описание финального (v3) состояния
и путь к нему.

## Цепочка работы

**Идея → промпт.** На входе — текстовое ТЗ (сохранено в PROMPT.md): CLI-приложение
с планом/фактом, отчётом план-факт и двумя диаграммами matplotlib; данные
в JSON, без внешних сервисов. Пользователь просил не задавать уточняющих
вопросов и фиксировать решения в README. Затем ТЗ дополнялось по ходу
работы: справочник категорий, перевод в веб, двухуровневые категории,
«деньги на виду» при заполнении плана и факта.

**Создание кода.** Код сразу разбит на модули: `models.py` (структура данных),
`storage.py` (JSON + ремонт), `validators.py` (ввод), `reports.py` (расчёты),
`charts.py` (диаграммы), `categories.py` (справочник) и точка входа
(`main.py` в v1, `app.py` в v2/v3). Палитра диаграмм прогнана через
скрипт-валидатор на CVD-дальтонизм до первого запуска. Каждый модуль
пишется с docstring и без магических чисел, как в ТЗ.

**Запуск и тесты.** Порядок по ТЗ: `pip install -r requirements.txt` →
`python demo.py` → `python smoke_test.py`. Smoke-тест гоняет логику
(данные, миграции, справочник, отчёт, диаграммы, валидацию) во временной
папке и печатает `OK`/`FAIL`; за три версии он поймал несколько реальных
ошибок (см. «Итерации»). Streamlit-часть автотестами не покрыта — решено
сразу, отмечается в отчётах.

**Ручная проверка.** После каждого смоук-прогона — взгляд на PNG
(цвета, наезды подписей, порядок секторов), прогон интерактивной сессии
через pipe со скриптованным вводом (в v1), headless-запуск Streamlit
с HTTP-проверкой и финально AppTest (в v3), затем живая работа в браузере.

**Итерации.** Правилось в несколько заходов: визуальные дефекты диаграмм
(слипшиеся подписи), забытые импорты, расхождение миграций с принятым
решением, утечка теста в боевые данные, рестарт сервера после рефакторинга.
Все исправления — под контролем повторного smoke-прогона.

**Результат.** Три локальных коммита на `main` (без пуша), 10 модулей,
smoke-тест `OK`, работающий сайт на http://localhost:8501 с выбором
месяца, планом по группам/подкатегориям, фактами, отчётом с раскрытием
и двумя диаграммами. Справочник стартует в репозитории, личные данные
(`data/budget.json`) — в `.gitignore`.

## Итерации и исправления

Каждая строка: что было не так → что изменил → как проверил.

1. **Слипшиеся подписи значений на столбцах** (визуальная проверка v1) →
   подписи убраны со всех столбцов («выборочные подписи»), значения читаются
   по оси Y → повторная визуальная проверка.
2. **Наезд подписей мелких секторов круговой** (v1: «3.2%» и «2.5%»
   поверх друг друга) → названия категории перенесены в легенду,
   проценты скрыты у секторов < 3% и вынесены за край круга
   (`pctdistance=1.15`) → визуальная проверка чисто.
3. **`NameError: wedges`** — `ax.pie()` вызывался без сохранения
   handle легенды → зафиксировал разрушение кортежа → smoke-тест
   поймал падение; после исправления `OK`.
4. **Отсутствовал `import models` / `import sys`** в `charts.py` и
   `categories.py` (после чистки CLI-функций) → импорты возвращены →
   smoke-тест упал/восстановлен до `OK`.
5. **Распаковка `value, _` в генераторе меню** (`validators.ask_choice`,
   v1) — внутри f-string использовалась переменная `description` →
   исправлена распаковка → E2E-сессия по pipe прошла все пункты меню.
6. **Символ «−» недоступен в cp1251-консоли** (краш `UnicodeEncodeError`
   при печати отчёта) → заменён на дефис + `stdout.reconfigure(errors="replace")`
   в точке входа → E2E-сессия прошла в cp1251-окружении.
7. **Миграция плоского справочника противоречила собственному решению**:
   незнакомые имена делались пустыми группами → по принятому решению
   отбрасываются (записи бюджета с ними уйдут в «Прочее») → миграция
   боевого плоского файла (восстановлен из git) дала ровно 9 групп/30
   подкатегорий.
8. **Утечка smoke-теста в боевые данные**: тест удаления статей вызывал
   `categories.remove_*` с дефолтным `path` и затёр настоящий
   `data/categories.json` → тест изолирован (файлы во временной папке,
   `path=` явный), справочник пересоздан → повторная визуальная проверка
   диаграмм подтвердила правильные цвета/порядок.
9. **Неверные ожидания в самом smoke-тесте** (демо-остаток 81 500 вместо
   68 500; «использования статей» 4 вместо 5; итерация по строке вместо
   `splitlines()`) → ассерты согласованы с реальными демо-цифрами →
   `OK`.
10. **Streamlit-сервер поднял старые модули**: сервер работал с до-рефакторных
    времён, Python держал старый `reports` в памяти → `AttributeError`
    при открытии страницы (браузер «не открывал localhost») → сервер
    остановлен и поднят заново, AppTest подтвердил исполнение страницы
    без исключений; в README добавлено правило «меняешь модули —
    перезапусти сервер».
11. **Незаконченная функция миграции** (`register_migrated_names` с
    относительным импортом) → удалена, дописывание имён в справочник
    переехало в `storage._migrate_flat_month_entries` → smoke-тест.

## Решения, принятые при разработке

1. **Streamlit** — рекомендация задания; вкладки, формы и диалоги из
   коробки без HTML/CSS; страница остаётся одним файлом `app.py`,
   вся логика — в чистых модулях.
2. **Данные по месяцам** (`{"months": {"YYYY-MM": …}}`) — селектор месяца
   должен отображать независимо ведущиеся месяцы; старые форматы
   (CLI и плоский) мигрируются автоматически при загрузке, ничего
   не теряется.
3. **План — редактирование, а не лента записей**: у подкатегории месяца
   одна плановая сумма (`set_planned_article` заменяет, 0 удаляет);
   иначе список полей в странице превратится в накопитель дублей.
4. **Удаление категории не теряет данные**: записи статьи переносятся
   в «Прочее» (подкатегория «Группа·Подкатегория» — т.к. одно имя
   бывает в разных группах; «Группа» при удалении группы целиком),
   «Прочее» защищено от удаления как приёмник.
5. **Входящий остаток — ручное число месяца** (допускает минус, как
   задолженность) — вычислить его из фактов невозможно, потому что
   факт-доходов в интерфейсе нет.
6. **Месяц планового дохода = селектор** (задание: «сумма, дата (месяц
   и год)»); у факта — полная дата своего поля.
7. **Сумма сохраняется только > 0** (ноль = «поле пустое»); отрицательные
   значения невозможны даже синтаксически (`min_value=0`) — «суммы
   неотрицательные» выполняются конструкцией интерфейса, а не текстом
   ошибки.
8. **Диаграммы только по группам** с палитрой по порядку справочника;
   разрез подкатегорий показывают таблицы отчёта — иначе десятки
   секторов перестают читаться.
9. **Smoke-тест не трогает пользовательские данные** — всё во временной
   папке; PNG и файлы миграций проверяются по отдельным путям.

## Известные ограничения

- Суммы — float с округлением до копеек (не `Decimal`).
- Фактических доходов (поступлений) в интерфейсе нет; «свободно» =
  входящий остаток + плановый доход − расходы.
- Записи нельзя редактировать (только удалить и заново).
- Плановый доход не имеет отдельного поля «месяц и год» — берётся
  из селектора.
- Записи с подкатегориями вне справочника отображаются серым и в конце
  списка.
- Streamlit-часть не покрыта автотестами (решено по заданию); AppTest
  используется только как диагностика запуска.
- Одна копия приложения на файл данных: параллельные записи из двух
  открытых вкладок могут затирать друг друга (нет блокировки файла).

## Чего не хватает по ТЗ

Код не меняю, перечисляю расхождения между исходными ТЗ (PROMPT.md,
PROMPT-дополнение) и текущей реализацией:

1. **Фактические доходы** — в CLI-ТЗ («Фактические доходы и расходы»)
   и в веб-вводе предполагались оба вида; в веб-версии по второму ТЗ
   в факт оставлены только расходы. Старые факт-доходы при миграции
   отбрасываются.
2. **Разрез mandatory/purchases** был обязателен в CLI-ТЗ (итоги расходов
   отдельно по двум типам) — в веб-версии не сохранён: план ведётся
   по подкатегориям, и «Обязательные/Покупки» как итоговая строка
   исчезли при переводе в группы.
3. **Дата планового дохода (месяц и год)** — в ТЗ она есть; реализована
   не отдельным полем, а сам селектором месяца (решение осознанное,
   но формально отдельного контрола нет).
4. **Меню-цикл с пунктом «выход»** из ТЗ v1 заменён на вкладки — то же
   ТЗ выполнено через иной интерфейс, консольная эргономика потеряна
   (восстанавливается checkout-ом коммита `4182686`).

Остальное из ТЗ (хранение JSON, валидация ввода, диаграммы с условием
«без трат — не строить», план-факт по категориям, шаблонные статьи,
управление категориями с дубликатами, фиксированные цвета, порядок
справочника) реализовано и проверено — см. таблицу «Что реализовано».

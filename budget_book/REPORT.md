# REF. v2: рефакторинг CLI-версии в Streamlit-приложение

Дата: 2026-11-08. Что изменилось относительно CLI-версии (коммит `4182686`)
и как это проверено.

## Что изменилось

### Интерфейс

| Было (CLI, `python main.py`) | Стало (Streamlit, `streamlit run app.py`) |
|---|---|
| Меню-цикл с номерами, ввод через `input()` | Страница с селектором месяца и вкладками «План» / «Факт» / «Отчёт» |
| Один месяц на файл | Месяцы раздельно в `data/budget.json`: `{"months": {"YYYY-MM": блок}}`; селектор сверху применяется к плану, фактам и отчёту |
| Категория выбирается из консольного списка по номеру | Статья выбирается `selectbox`-ом; новая статья добавляется в диалоге и сразу появляется в группе шаблонных |
| Планированные расходы вводились по одной записи (mandatory/purchases) | План по статьям редактируется списком сумм прямо по всем шаблонным статьям (одна форма), ноль = без плана |
| — | Таблица отчёта: статья, план, факт, **разница**, **процент от плана**; сводка «план доходов / план расходов / факт / остаток» в метриках |
| — | Плановый доход: источник + сумма (месяц и год берутся из селектора — отдельной даты не нужно) |

### Скрытые изменения

- `main.py` удалён (точкой входа стал `app.py`); CLI-код доступа в
  git-истории.
- `models.py` переписан под месяцы; добавлена
  `models.migrate_legacy_budget()` — старые CLI-данные (`budget.json`
  с планом в корне и обязательными платежами/покупками) автоматически
  переносятся в текущий месяц: статьи сливаются по категориям,
  `name` расхода становится комментарием.
- `storage.load_budget()` теперь понимает оба формата и чинит только
  повреждённые файлы (испорченная копия переносится в
  `data/budget.corrupt.json`); при чтении старого CLI-файла миграция
  выполняется на лету, файл сразу пересохраняется в новом формате.
- `validators.py` урезан до чистых функций (`parse_amount` — запятая
  как разделитель, пробелы, ноль как «пустое поле»; `clean_text`),
  CLI-циклов ввода больше нет — Streamlit ограничивает ввод сам.
- `categories.py` урезан до программной части (файл, добавление,
  нормализация, цветовой индекс); консольный выбор по номеру удалён.
- `charts.py` считает диаграммы по выбранному месяцу; палитра осталась
  привязанной к индексу статьи в справочнике.
- Факт-доходы убраны из интерфейса (в задании для веб-версии ввод
  только фактических расходов); «Остаток факт» считается по расходам,
  это записано в README (Решения, п. 6).
- `requirements.txt`: добавлен `streamlit==1.67.0` (Python 3.14
  совместим), `matplotlib==3.11.2` без изменений.

### Данные

- `data/budget.json` — формат по месяцам (`months`).
- `data/categories.json` — прежний справочник статей, дефолтный список
  тот же; файл по-прежнему в репозитории.
- `data/budget.json` CLI-формата, лежавший на момент рефакторинга в `data/`,
  заменён запуском `demo.py` на новый формат; сам путь миграции старых
  данных проверен отдельным кейсом smoke-теста (`run_storage_and_demo`).

## Как проверено

1. `python smoke_test.py` — **OK**. Все части зелёные:
   - данные: месяца, план статей, замена/удаление нулём, **миграция
     CLI-формата** (слияние mandatory/purchases → статья, name →
     комментарий);
   - справочник: добавление, отказ на дубликаты без учёта регистра
     и пробелов, цветовой индекс, восстановление из дефолта после порчи
     файла (во временной папке);
   - отчёт за месяц: план/факт статьи «Жильё» (36 000 / 35 200),
     разница (800), процент (97.8%), прочерк при нулевом плане,
     пустой месяц → «(нет данных)»;
   - диаграммы: обе PNG строятся на данных месяца; круговая не
     строится при пустом факте;
   - валидация: `99,50` → 99.5, `1 000` → 1000, ноль/отрицательные/
     нечисловое/"NaN"/"inf"/`1e400` отклоняются, пустая строка не
     сохраняется.
2. Python 3.14.8: `py_compile` по всем модулям; Streamlit-приложение
   запущено headless на порту 8765 и `urllib` получил HTTP 200
   со стандартной страницей Streamlit.
3. Streamlit-часть (клики, вкладки, диалоги) — **вручную не тестируется
   автоматически** по требованию задания: smoke-тест покрывает логику
   моделей/отчёта/диаграмм/справочника, а Streamlit-интерфейс
   проверяется человеком при обычном запуске
   (`streamlit run app.py`). Автоматической имитации ввода через
   AppTest не делалось сознательно.
4. Логика миграции проверена на синтетическом CLI-файле (временная
   папка, пользовательские данные не затрагиваются).

# v3: двухуровневые категории (группы и подкатегории)

Дата: 2026-11-08. Коммит «refactor: двухуровневые категории».

## Что изменилось и почему

### Справочник

- `data/categories.json` теперь словарь «группа → список подкатегорий»:
  `{"Жильё": ["Аренда", "Коммунальные услуги", ...], "Здоровье": [...]}`.
- 9 дефолтных групп, 30 подкатегорий (список у пользователя).
- API справочника: `add_group` (пустая или сразу с подкатегориями),
  `add_subcategory`, `remove_group`, `remove_subcategory`; коды
  возврата `ADDED | REMOVED | DUPLICATE | NO_GROUP`. Дубликаты — без
  учёта регистра и внешних пробелов.

## Миграции (решения)

1. **Плоский справочник** (v1/v2, список строк): знакомые имена
   (Жильё, Транспорт, Здоровье, Развлечения, Одежда, Прочее) становятся
   группами с дефолтными подкатегориями; незнакомые (Продукты,
   Образование, Подписки, Подарки, «Связь и интернет») отбрасываются —
   они бесполезны без подкатегорий, а записи бюджета с ними уходят
   в «Прочее» (следующий пункт). Плоский файл сохраняется рядом как
   `categories.corrupt.json`.
2. **Записи бюджета с плоскими категориями** (v1 и v2): переезжают
   в группу «Прочее» как подкатегории с прежними названиями
   (рекомендация задания); имена дописываются в справочник «Прочее»,
   чтобы записи остались выбираемыми. Выполняется при загрузке
   бюджета (storage) — `models.migrate_flat_entries` для v2-блоков и
   `models.migrate_legacy_budget` для CLI-формата (плюс слияние
   mandatory/purchases по категории в одну сумму «Прочее/<имя>»).
3. **Удаление статей через вкладку «Категории»**: удаление — не «пустое»
   молчание, а перенос. Если по удаляемой подкатегории/группе уже есть
   план или факт (счётчик `models.count_article_usage` выводится
   предупреждением), записи автоматически переезжают:
   - удалена подкатегория «Аренда» → план/факт в «Прочее/Жильё·Аренда»;
   - удалена группа «Жильё» → план/факт в «Прочее/Жильё».
   Так ничего не теряется, и «Прочее» остаётся честным разрезом.
   Группу «Прочее» удалить нельзя — это приёмник миграций.
4. **Двойная система имён при переносе**: для подкатегории используется
   метка «Группа·Подкатегория», потому что одно имя может быть
   подкатегорией разных групп; для группы целиком — просто имя группы.

## Интерфейс (что добавилось)

- **Вкладка «Категории»**: справочник списком (группы + подтянутые
  подкатегории), добавить группу (опционально сразу с подкатегориями,
  по одной в строке), добавить подкатегорию в существующую группу,
  удалить группу/подкатегорию (с предупреждением и переносом данных).
- **Вкладка «План»**: поля плана по подкатегориям, сгруппированным
  заголовками («Жильё», под ним Аренда, Коммунальные услуги и т.д.).
- **Вкладка «Факт»**: два зависимых списка — сначала группа, потом
  её подкатегория; сумма, дата, комментарий.
- **Вкладка «Отчёт»**: компактная таблица по группам (план/факт/
  разница/%-от-плана; прочерк при нуле) + по каждой группе expander
  «Жильё: план 36 000, факт 39 000» с таблицей по подкатегориям.
- **Деньги «на виду»** (дополнение по ходу работы): во вкладке «План» —
  редактируемый входящий остаток, плановый доход быстрым разрезом
  (Зарплата/Подработка/Прочий доход), план расходов и «свободно»
  (остаток + доходы − план); отрицательное значение — сообщение
  о перерасходе. Во вкладке «Факт» сводка повторяется сверху, но с
  фактом трат: остаток «доход − расход» виден при заполнении.
- **Диаграммы** — обе только по группам; палитра привязана к порядку
  групп в справочнике (первые 9 слотов проверенной палитры), цвет
  группы одинаков на обеих диаграммах; проверены визуально после
  миграции и после каждого прогона.

## Как проверено

1. `python smoke_test.py` — **OK**, все части зелёные:
   - месяцы, план по (группа, подкатегория), замена/удаление нулём,
     входящий остаток (в т.ч. отрицательный);
   - миграция v2-записей → «Прочее/<имя>» (и список перенесённых имён)
     и CLI-формата (слияние mandatory/purchases);
   - справочник: добавление группы с/без подкатегорий, дубликаты
     (регистр, пробелы) — отказ; подкатегория в несуществующую группу
     — отказ; миграция плоского файла (знакомые — с дефолтными
     подкатегориями, незнакомые — отброшены); повреждённый файл
     восстанавливается из дефолта — всё во временной папке;
   - удаление статьи: подсчёт использований (план+факт) верный,
     записи переносятся в «Прочее» с метками «Жильё·Аренда» и «Жильё»;
   - отчёт: план/факт/разница/процент групп и подкатегорий на
     демо-данных (Жильё 36 000/39 000, diff −3 000 — перерасход виден),
     строка «(без подкатегорий)», «(нет данных)» для пустого месяца;
   - диаграммы: обе PNG по группам строятся, круговая не строится без
     трат;
   - валидация сумм: как раньше (запятая, пробелы, ноль, мусор).
2. Миграция в боевых условиях: настоящий плоский `data/categories.json`
   восстановлен из git-истории (v2) и мигрирован загрузкой — 9 групп,
   30 подкатегорий, цвета групп по порядку (проверено на готовых PNG).
3. Streamlit-приложение запущено headless (HTTP 200) — как в v2.
   Интерактив (кнопки/диалоги/зависимые списки) — вручную пользователем.
4. Побочный дефект, найденный и исправленный по ходу: smoke-тест
   удаления статей писал в настоящий справочник (дефолтный `path` в
   `remove_*`) — тест изолирован с временным файлом, справочник
   пересоздан из дефолта.

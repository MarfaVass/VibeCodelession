## 3. Результат «отличного» промпта (ответ ИИ)

ChatGPT выдал функцию с двумя ключевыми регулярками:

```python
import re
from collections import Counter


def analyze_text(text: str) -> dict:
    # Приводим текст к нижнему регистру
    text = text.lower()

    # Слова — только последовательности букв (русских и английских)
    words = re.findall(r"[a-zа-яё]+", text)

    # «Предложения» — группы знаков . ! ?
    sentences = re.findall(r"[.!?]+", text)

    if not words:
        return {
            "word_count": 0,
            "unique_words": 0,
            "top_3_words": [],
            "avg_word_length": 0,
            "sentence_count": 0,
        }

    word_frequencies = Counter(words)
    top_3_words = word_frequencies.most_common(3)

    avg_word_length = round(
        sum(len(word) for word in words) / len(words), 2
    )

    return {
        "word_count": len(words),
        "unique_words": len(word_frequencies),
        "top_3_words": top_3_words,
        "avg_word_length": avg_word_length,
        "sentence_count": len(sentences),
    }
```

Плюс 4 собственных теста ИИ: обычный текст, пустая строка, строка из пробелов, текст только с пунктуацией. Все четыре проходят.

### 4.3. Выявленные ошибки

| № | Ошибка | Как проявляется | Причина в коде |
|---|--------|-----------------|----------------|
| 1 | **Падение на `None` и не-строках** | `analyze_text(None)` → `AttributeError: 'NoneType' object has no attribute 'lower'`; то же для `123`, `["x"]`, `True` | `text.lower()` вызывается до проверки типа |
| 2 | **Апостроф режет слово** | `don't` → `don` + `t`; `It's` → `it` + `s`; `John's` → `john` + `s`. Буква `s` попадает в топ-3, `avg_word_length` занижена до 2.33 | `re.findall(r"[a-zа-яё]+")` — апостроф не буква, режет |
| 3 | **`sentence_count` считает группы знаков, а не предложения** | `"Привет"` → 0 (должно 1); текст без финальной точки → 1 (должно 2); `"Привет... мир"` → 1 (должно 2); `"Привет!!!"` → 1 (случайно верно) | `len(re.findall(r"[.!?]+", text))` — считает группы `.`/`!`/`?`, а не фрагменты между ними |
| 4 | **Числа молча сливаются** | `"Python3 лучше Python2"` → `word_count = 3`, `unique_words = 2`: `Python3` и `Python2` оба стали `python` | Класс `[a-zа-яё]` не содержит цифр — они выкидываются, а не разделяют слово |
| 5 | **Дроби, версии, сокращения → ложные «предложения»** | `"Версия 3.11"` → `sentence_count = 1`; `"Т.е. так"` → 2; `"example.com"` → 1 | `[.!?]+` ловит точку в числе/сокращении/URL как терминатор |

**Что работает корректно (проверено):**

| Ловушка | Результат |
|---------|-----------|
| Дефис | `из-за` → `из` + `за`, `hello-world` → `hello` + `world` — верно (побочно, но верно) |
| Регистр + кириллица | `"Привет ПРИВЕТ hello HELLO"` → `unique_words = 2` — верно |
| Пунктуация внутри | `"слово, слово; слово"` → `word_count = 3` — верно |
| Топ-3 при равных частотах | Стабилен (`Counter.most_common` сохраняет порядок появления) |

**Особо важное наблюдение:** пример из промпта `"Привет, мир! Привет, Python. Как дела?"` → `sentence_count = 3` проходит **случайно**: в нём каждая фраза заканчивается ровно одним терминатором, поэтому «число групп знаков» совпало с «числом предложений». Как только это совпадение ломается (текст без финальной точки, многоточие внутри), код врёт. Это классическая проблема: **ИИ проверяет себя по своим же тестам**, и на «удобных» примерах всё идеально, а на соседних входах логика разваливается.

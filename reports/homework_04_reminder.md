# Домашнее задание № 4. Разработка приложения «Напоминалка»

## 1. Цель проекта

Разработать десктопное приложение на Python для создания задач и управления напоминаниями. Приложение должно иметь графический интерфейс, сохранять данные между запусками, поддерживать несколько сигналов для одной задачи и позволять пользователю управлять выполнением и переносом напоминаний.

В процессе работы проект прошёл два основных этапа: создание первоначальной рабочей версии и последующую доработку логики напоминаний по результатам использования.

**Основная ветка:** `main`

## 2. Техническое задание

### 2.1. Основные требования

Необходимо разработать локальное десктопное приложение со следующими возможностями:

1. Создание задачи с названием, описанием и датой и временем напоминания.
2. Отображение списка задач с возможностью фильтрации по статусу.
3. Хранение задач в базе данных, чтобы данные не исчезали после закрытия программы.
4. Поддержка статусов задач: ожидание, выполнение, отмена.
5. Отображение уведомлений при наступлении заданного времени.
6. Возможность отметить задачу выполненной или отменить её.
7. Возможность отложить напоминание.
8. Поддержка нескольких сигналов для одной задачи.
9. Отмена оставшихся сигналов после завершения задачи.
10. Корректная работа с несколькими задачами, напоминания по которым могут наступать в разное время.

### 2.2. Требования к логике напоминаний

В первоначальной версии использовалась более простая схема напоминаний. В ходе доработки модель была изменена.

Для задачи задаётся контрольное время X. Пользователь может выбрать несколько сигналов:

- до контрольного времени — например, за 60, 30, 15 или 5 минут;
- непосредственно в контрольное время;
- после контрольного времени — например, через 5, 15, 30 или 60 минут.

Сигналы необязательны: пользователь самостоятельно выбирает подходящие интервалы.

При завершении задачи все её оставшиеся сигналы должны отменяться. Завершённая задача не должна продолжать показывать уведомления.

При переносе напоминания пользователь выбирает интервал отсрочки. Перенос не должен автоматически означать выполнение задачи.

Закрытие окна напоминания не должно приравниваться к нажатию кнопки «Выполнено».

### 2.3. Технологические требования

- Python — основной язык программирования.
- Tkinter — графический интерфейс.
- SQLite — локальное хранение данных.
- `datetime` — вычисление времени сигналов.
- Git и GitHub — контроль версий и хранение исходного кода.

## 4. Доработки после первого этапа

### 4.1. Переход к контрольному времени X

Вместо единственного напоминания стала использоваться модель с контрольным временем задачи и несколькими дополнительными сигналами.

Пользователь может заранее настроить расписание уведомлений до контрольного времени, в сам момент X и после него.

Это позволяет использовать приложение для задач, которые требуют подготовки, контроля срока и повторного напоминания после наступления назначенного времени.

### 4.2. Разделение действий пользователя

Логика взаимодействия с уведомлением была уточнена.

**«Выполнено»**

- задача переводится в статус «Готово»;
- оставшиеся сигналы этой задачи отменяются;
- завершённая задача больше не должна напоминать о себе.

**«Напомнить позже»**

- пользователь выбирает интервал отсрочки;
- время сигнала переносится;
- перенос не означает завершение задачи.

**Закрытие окна**

Закрытие окна не должно автоматически переводить задачу в статус «Готово». Сам факт закрытия окна и подтверждение выполнения — разные действия.

### 4.3. Работа с несколькими сигналами

У одной задачи может быть несколько запланированных событий. Поэтому при выполнении необходимо отменять не только сигнал, который сейчас отображается, но и остальные ожидающие сигналы этой задачи.

В ходе проверки было подтверждено, что после нажатия «Выполнено» задача получает статус «Готово», а количество оставшихся напоминаний в списке становится равным нулю.

### 4.4. Работа с несколькими задачами

Уведомления разных задач могут наступать в разное время.

При появлении следующего уведомления приложение должно сохранять независимость задач: выполнение одной задачи не должно автоматически завершать другую.

В ходе проверки пользователь наблюдал последовательное появление окон для задач, напоминания которых наступили в разное время. Это позволило проверить поведение приложения при наличии нескольких ожидающих задач.

### 4.5. Изменения интерфейса

В процессе доработки были уточнены настройки сигналов и поведения элементов управления.

В частности, изменены значения флажков по умолчанию:

- «В назначенное время» — включён;
- «Через 15 минут» — выключен.

Это позволяет не включать дополнительный сигнал автоматически, если пользователь не выбрал его самостоятельно.

Также была уточнена обработка ситуации, когда пользователь пытается отложить напоминание, не выбрав интервал отсрочки.

### 4.6. База данных

Логика хранения данных была адаптирована к работе с отдельными событиями напоминаний и их статусами.

При завершении задачи приложение должно обновлять её состояние и отменять оставшиеся сигналы. При переносе напоминания изменяется время соответствующего события.

База данных SQLite остаётся локальной. Файл `reminders.db` создаётся приложением и не должен попадать в репозиторий как пользовательская база с тестовыми данными.

# Домашнее задание № 2. Организация Git-репозитория

**Дата выполнения:** 20 октября 2026 года  
**Тема:** Git, GitHub, структура Python-проекта и документация.

## 1. Цель задания

Привести существующий учебный Python-проект в порядок, сохранить историю изменений, подготовить понятную документацию и опубликовать результат на GitHub.

В результате должен получиться репозиторий, в котором:

- файлы проекта организованы по назначению;
- локальное виртуальное окружение не хранится в Git;
- программа запускается;
- README объясняет назначение проекта и порядок запуска;
- история изменений сохранена и опубликована.

## 2. Исходное состояние

До начала работы в проекте уже были:

- локальный Git-репозиторий;
- удалённый репозиторий GitHub;
- Python-скрипт для получения информации о товаре через API;
- файл README;
- виртуальное окружение `venv`.

При этом локальная история Git отличалась от удалённой. В README возник конфликт при объединении версий. Также требовалось исключить виртуальное окружение из отслеживания Git, не удаляя его с компьютера.

## 3. Что было сделано

### 3.1. Настройка `.gitignore`

**Задача:** исключить из Git виртуальное окружение и временные файлы.

В `.gitignore` добавлены правила:

```gitignore
venv/
.venv/
__pycache__/
*.py[cod]
.env
.vscode/
```

**Зачем это нужно:**

- `venv/` и `.venv/` — локальные виртуальные окружения с установленными библиотеками;
- `__pycache__/` и `*.py[cod]` — служебные файлы Python;
- `.env` — файл, в котором могут храниться локальные настройки и секреты;
- `.vscode/` — локальные настройки редактора.

Виртуальное окружение уже попало в индекс Git, поэтому одного `.gitignore` было недостаточно. Его пришлось убрать из индекса, сохранив локальную папку.

**Результат:** правило исключения проверено командой `git check-ignore`. Локальное виртуальное окружение осталось на компьютере.

### 3.2. Организация Python-файлов

Скрипты размещены в папке `main`:

- `main/main.py` — проверка карточки товара;
- `main/fetch_product.py` — получение данных о товаре через API.

Так программы сгруппированы в одном месте, а документация и настройки проекта остаются в корневой папке.

### 3.3. Создание программы проверки карточки товара

Файл `main/main.py` содержит функцию `check_product_card(title, price, description)`.

Она проверяет три условия:

1. Название товара не должно быть пустым.
2. Цена должна быть больше нуля.
3. Описание товара не должно быть пустым.

Если обнаружены ошибки, функция возвращает список замечаний. Если ошибок нет, программа сообщает об успешной проверке.

**Зачем это было сделано:** программа демонстрирует простой пример автоматизации рутинной задачи из предметной области проекта — проверки заполнения карточки товара. Она также позволяет проверить, что Python-код запускается после организации репозитория.

**Проверка результата:** выполнена команда:

```powershell
python .\main\main.py
```

Для тестовой карточки разделочной доски ComposeEat с ценой 2490 программа сообщила, что карточка заполнена корректно.

Это базовый учебный пример. Он пока не проверяет реальные карточки из интернет-магазина и не заменяет полноценный контроль качества товарного контента.

### 3.4. Обновление README

В `README.md` добавлены:

- описание проекта;
- назначение программы;
- список проверяемых полей;
- требования к запуску;
- команда запуска;
- структура папок;
- идеи для дальнейшего развития.

**Зачем:** README помогает другому человеку понять назначение проекта без изучения исходного кода и быстро запустить программу.

### 3.5. Объединение истории Git

Локальный репозиторий и GitHub содержали разные исходные истории. Чтобы сохранить обе, была получена информация с удалённого репозитория и выполнено объединение с разрешением объединять истории без общего предка.

При объединении возник конфликт README. Итоговый файл был отредактирован вручную, после чего конфликт был разрешён и создан коммит объединения.

**Результат:** локальная и удалённая истории объединены без принудительной перезаписи ветки GitHub.

### 3.6. Отправка на GitHub

После завершения изменений выполнена команда:

```powershell
git push origin main
```

Git подтвердил обновление удалённой ветки `main` с коммита `1160b14` до `0f2464f`.

После отправки проект был открыт в браузере. Файлы и README доступны на GitHub, история содержит восемь коммитов.

## 4. Использованные команды Git и PowerShell

| Команда                                                  | Назначение                                                                    |
| -------------------------------------------------------- | ----------------------------------------------------------------------------- |
| `git status --short`                                     | Кратко показать изменения и неотслеживаемые файлы                             |
| `git status --short \| Select-Object -First 20`          | Ограничить вывод первыми строками при большом количестве файлов               |
| `git add .gitignore`                                     | Подготовить `.gitignore` к коммиту                                            |
| `git reset`                                              | Снять изменения с подготовки к коммиту, не отменяя сами изменения файлов      |
| `git check-ignore -v --no-index venv/Scripts/python.exe` | Проверить, каким правилом исключается файл виртуального окружения             |
| `git rm -r --cached venv`                                | Удалить `venv` из индекса Git, сохранив локальные файлы                       |
| `git fetch origin`                                       | Получить сведения об удалённой ветке без автоматического объединения          |
| `git merge origin/main --allow-unrelated-histories`      | Объединить локальную и удалённую истории, изначально не имевшие общего предка |
| `git add README.md`                                      | Подготовить разрешённый конфликт README к коммиту                             |
| `git commit -m "Merge GitHub history"`                   | Зафиксировать объединение историй                                             |
| `python .\main\main.py`                                  | Запустить проверку карточки товара                                            |
| `git push origin main`                                   | Отправить локальные коммиты в удалённую ветку `main`                          |

Дополнительные команды, использованные в ходе работы:

```powershell
git rebase --abort
Test-Path .\venv\Scripts\python.exe
```

`git rebase --abort` использовалась для попытки отменить незавершённый rebase. Операция столкнулась с блокировкой `index.lock`; после этого работа с историей продолжилась через безопасное объединение веток.

`Test-Path` — команда PowerShell, а не Git. Она проверяет, существует ли указанный файл или папка. С её помощью проверили, что локальный интерпретатор Python в `venv` сохранился.

## 5. Возникшие трудности и решения

**Проблема 1. Виртуальное окружение попало в Git.**

Решение: добавлены правила `.gitignore`, а уже отслеживаемые файлы `venv` удалены из индекса через `git rm -r --cached venv`.

**Проблема 2. Локальная и удалённая истории различались.**

Решение: получены сведения об удалённой ветке, затем истории объединены без принудительной перезаписи GitHub.

**Проблема 3. Конфликт README.**

Решение: подготовлена итоговая версия документа, конфликт разрешён, изменения зафиксированы коммитом.

**Проблема 4. Большой вывод Git со списком файлов `venv`.**

Решение: для дальнейшей проверки использовались команды с фильтрацией вывода, чтобы видеть только нужную информацию.

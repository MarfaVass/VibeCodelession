# OOP_base — архитектура и техническое задание

Учебная консольная система управления задачами Todo на Python.

Домашнее задание VPb04 «Основы объектного мышления».

## 1. Цель проекта

Продемонстрировать базовое объектно-ориентированное мышление на Python:

- три связанных класса, каждый отвечает за свои данные и действия;
- инкапсуляция через приватные атрибуты и свойства `@property`;
- автоматическая генерация ID;
- проверка входных данных;
- взаимодействие объектов через их методы, а не через прямой доступ к данным.

Проект намеренно учебный: без базы данных, API, GUI, авторизации, ORM,
асинхронности и сторонних библиотек. Всё хранится в памяти.

## 2. Модель предметной области

Иерархия объектов:

```text
User (пользователь)
└── Project (проект)   ← пользователь владеет списком проектов
    └── Task (задача) ← проект владеет списком задач
```

- Пользователь содержит список проектов.
- Проект содержит список задач.
- Каждый объект сам управляет своими данными и имеет собственные методы.

## 3. Классы

### 3.1. Task — отдельная задача

Атрибуты (приватные):

| Атрибут | Тип | Назначение |
|---|---|---|
| `_id` | int | ID задачи, назначается проектом при добавлении |
| `_title` | str | Название задачи |
| `_description` | str | Описание задачи |
| `_due_date` | str \| None | Срок в формате `YYYY-MM-DD` (ISO), может отсутствовать |
| `_status` | str | Статус: `todo` → `in_progress` → `done` |

Методы:

- `change_description(new_description)` — изменить описание;
- `change_due_date(new_due_date)` — изменить срок;
- `set_status(new_status)` — изменить статус;
- `complete()` — отметить задачу выполненной;
- `info` (свойство) — краткая сводка о задаче одной строкой.

Свойства для чтения: `id`, `title`, `description`, `due_date`, `status`.

Проверка данных:

- название не может быть пустой или состоять из пробелов строкой;
- описание не может быть пустой строкой;
- дата срока должна быть корректной датой в формате `YYYY-MM-DD`;
- статус должен быть одним из `todo`, `in_progress`, `done`.

Нарушения вызывают `ValueError` с понятным сообщением на русском.

### 3.2. Project — проект с задачами

Атрибуты (приватные):

| Атрибут | Тип | Назначение |
|---|---|---|
| `_id` | int | ID проекта, назначается автоматически (счётчик класса) |
| `_name` | str | Название проекта |
| `_tasks` | list[Task] | Список задач проекта |
| `_next_task_id` | int (class-level) | Счётчик для выдачи ID новым задачам |

Методы:

- `add_task(title, description, due_date=None)` — создать задачу в проекте;
- `remove_task(task_id)` — удалить задачу по ID;
- `get_task_by_id(task_id)` — найти задачу по ID (или `None`);
- `mark_task_status(task_id, status)` — изменить статус задачи;
- `complete_task(task_id)` — отметить задачу выполненной;
- `find_tasks_by_status(status)` — отфильтровать задачи по статусу;
- `tasks` (свойство) — список задач (копия, чтобы снаружи список не изменили);
- `progress` (свойство) — процент выполненных задач, целое число 0–100;
- `info` (свойство) — сводка о проекте одной строкой.

Свойства для чтения: `id`, `name`.

Проверка данных:

- название не может быть пустой или состоять из пробелов строкой;
- ID задачи — целое число; если задачи с таким ID нет, возникает `KeyError`;
- статус задачи проверяет сама задача;
- пустой проект имеет прогресс `0` (защита от деления на ноль).

### 3.3. User — пользователь системы

Атрибуты (приватные):

| Атрибут | Тип | Назначение |
|---|---|---|
| `_name` | str | Имя пользователя |
| `_projects` | list[Project] | Список проектов пользователя |

Методы:

- `create_project(name)` — создать проект и добавить в список;
- `add_project(project)` — добавить уже созданный проект;
- `remove_project(project_id)` — удалить проект по ID;
- `get_project_by_id(project_id)` — найти проект по ID (или `None`);
- `find_project_by_name(name)` — найти проект по точному названию (или `None`);
- `projects` (свойство) — список проектов (копия);
- `info` (свойство) — сводка о пользователе одной строкой.

Свойства для чтения: `name`.

Проверка данных:

- имя не может быть пустой или состоять из пробелов строкой;
- названия проектов одного пользователя не должны повторяться;
- ID проекта — целое число; если проекта с таким ID нет, возникает `KeyError`.

## 4. Правила взаимодействия объектов

- Объекты общаются только через публичные методы и свойства.
- Списки `tasks` и `projects` наружу отдаются как копии — внешний код не может
  подменить содержимое в обход методов.
- Задача не знает о проекте и пользователе; проект не знает о пользователе.
  Связь направлена от верхнего уровня к нижнему.
- ID задач генерирует проект (передает ID в конструктор задачи).
- ID проектов генерирует счетчик на уровне класса `Project`.

## 5. Обработка некорректных данных

Все проверки входных данных выполняются в конструкторах и методах-мутаторах:

- пустые строки и строки из одних пробелов — `ValueError`;
- неверный формат даты — `ValueError`;
- неизвестный статус — `ValueError`;
- дубликат названия проекта — `ValueError`;
- поиск несуществующего ID без удаления — возвращает `None`;
- удаление несуществующего ID — `KeyError`;
- удаление проекта из `main.py` демонстрируется в блоке `try/except`.

## 6. Демонстрационный сценарий

В конце `main.py` под `if __name__ == "__main__":` выполняется автоматическая
демонстрация, которая последовательно показывает:

1. создание пользователя и двух проектов;
2. добавление задач с разными сроками и статусами;
3. изменение описания и срока задачи, смену статусов;
4. прогресс проекта до и после выполнения задач;
5. поиск задач и проектов по ID;
6. фильтрацию задач по статусу;
7. удаление задачи и проекта;
8. обработку некорректных данных (пустое имя, дубликат проекта, неверная дата, неудаление несуществующей задачи) через `try/except`.

## 7. Тесты

Папка `tests/`, стандартный `unittest`, без сторонних зависимостей:

- создание объектов и генерация ID;
- валидация названий, дат, статусов и дубликатов;
- прогресс пустого проекта;
- поиск и удаление объектов;
- иммутабельность списков, отдаваемых наружу.

## 8. Ограничения (что сознательно не делаем)

- Нет сохранения на диск и в базу данных: данные живут в памяти.
- Нет GUI и интерактивного меню — поведение демонстрирует демо-сценарий.
- Нет сторонних библиотек: только стандартная библиотека Python.

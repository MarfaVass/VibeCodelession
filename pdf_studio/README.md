# PDF Studio

Графическое приложение (Tkinter) для генерации деловых PDF-документов.
Наследует механизм домашнего проекта `pdf_checkmaker`: HTML-шаблон Jinja2 →
PDF (WeasyPrint) → автоматическое открытие файла. Новые pip-зависимости
**не требуются** — используются Tkinter и библиотеки, уже установленные в
виртуальном окружении репозитория (`weasyprint`, `jinja2`).

## Сценарии

| Сценарий | Статус | Что делает |
|---|---|---|
| **Создать сертификат** | ✅ реализован | Персональный PDF-сертификат (A4 альбомный) по полям формы |
| **Отчет о продажах** | ✅ реализован | Аналитический PDF-отчет по CSV с выбором разделов |
| **Коммерческое предложение** | ✅ реализован | PDF-предложение по выбранным позициям каталога CSV |

## Структура проекта

```
pdf_studio/
├── app.py                      # Главное окно: выбор одного из трех сценариев
├── common/                     # Общие модули всех сценариев
│   ├── paths.py                # Каталоги проекта (относительно кода)
│   ├── errors.py               # DataError — понятные ошибки на русском
│   ├── csv_io.py               # Чтение CSV (utf-8-sig → cp1251)
│   ├── numfmt.py               # Форматы денег/количества ('1 234,50')
│   ├── validation.py           # Валидация полей форм (не зависит от Tkinter)
│   └── pdf_output.py           # Рендер → PDF → уникальное имя → открытие
├── documents/
│   ├── certificate.py          # Логика сценария «Сертификат» (без Tkinter)
│   ├── sales_report.py         # Расчеты отчета о продажах (без Tkinter)
│   └── quotation.py            # Каталог, фильтры, скидки, суммы КП
├── gui/
│   ├── certificate_frame.py    # Окно формы сертификата
│   ├── sales_frame.py          # Окно отчета о продажах
│   ├── quotation_frame.py      # Окно коммерческого предложения
│   └── tk_helpers.py           # Ctrl+V/C/X/A в полях (работа с раскладками)
├── templates/
│   ├── certificate.html        # Шаблон сертификата (A4 landscape)
│   ├── sales_report.html       # Шаблон отчета о продажах (A4)
│   └── quotation.html          # Шаблон коммерческого предложения (A4)
├── data/
│   ├── sales.csv               # Демонстрационные данные о продажах
│   └── catalogue.csv           # Демонстрационный каталог товаров
├── tests/
│   ├── test_certificate.py     # unittest бизнес-логики сертификата
│   ├── test_sales.py           # unittest расчетов отчета о продажах
│   ├── test_quotation.py       # unittest коммерческого предложения
│   └── test_tk_helpers.py      # unittest шорткатов Ctrl+V/C/X/A
└── output/                     # Готовые PDF (создается приложением)
```


Во всех полях ввода работают **Ctrl+V / Ctrl+C / Ctrl+X / Ctrl+A**, в том числе при активной русской раскладке (шорткаты привязаны к коду клавиши, а не к языку);
## Запуск на Windows (PowerShell)

Используется уже существующее виртуальное окружение `venv` в корне
репозитория. Откройте PowerShell **в корне репозитория** и выполните:

```powershell
# Вариант 1: с активацией окружения
.\venv\Scripts\Activate.ps1
python pdf_studio\app.py

# Вариант 2: прямым путем к python.exe (из любой папки)
.\venv\Scripts\python.exe pdf_studio\app.py
```

Запускать надо именно `pdf_studio\app.py` — он открывает главное окно.
Совсем без консоли: двойной клик по файлу `pdf_studio\PDF Студио.bat`
(работает и с Рабочего стола). Это **упрощенный запуск**: bat-файл сам находит
интерпретатор, но окружение `venv` и библиотеки должны быть уже установлены —
автономной установки приложение не выполняет.
Старый консольный `pdf_checkmaker\pdf_generator.py` продолжает работать
как раньше, приложение его не изменяло.

Результат сохраняется в `pdf_studio\output\` с меткой времени в имени
(например, `certificate_2026-10-28_14-32-07.pdf`) — ранее созданные
документы **никогда не перезаписываются** — и сразу открывается в
программе просмотра документов Windows.

## Окно «Создать сертификат»

- **Имя получателя** и **курс/мероприятие/номинация** — обязательные поля;
  при пустых приложение показывает понятное сообщение на русском.
- **Дата** — формат ДД.ММ.ГГГГ, по умолчанию сегодняшняя; некорректная
  дата (например `31.02.2026`) отклоняется с сообщением.
- **Организация** — необязательное, по умолчанию «Курс вайб-кодирования».
- **Номер** — необязательное; кнопкой «Сгенерировать номер» или
  автоматически при создании: `PS-ГГГГММДД-NNNN`.
- Кнопка **«Заполнить пример»** подставляет демонстрационные данные
  (шуточная номинация) для быстрого показа приложения.

Шаблон сертификата печатается с двойной золотой рамкой и содержит
заметку, что документ носит поздравительный характер и не является
документом об образовании или квалификации.

## Сценарий «Отчет о продажах»

Шаги в окне:

1. Нажмите «Выбрать CSV…» и укажите файл с продажами (при открытии окна
   автоматически загружается демонстрационный `data/sales.csv`).
   Кнопка **«Загрузить демо-файл»** возвращает демонстрационные данные
   в один клик; если вы сами выбирали файл, спросит подтверждение и не
   подменяет его незаметно.
2. Под путем отображается статистика: количество прочитанных товаров,
   всего единиц и число пропущенных некорректных строк.
3. Отметьте чекбоксами разделы, которые должны попасть в PDF
   (по умолчанию выбраны все). Флажки независимы: можно как свернуть
   отчет кнопкой «Минимальный отчет» (основные показатели + таблица),
   так и снять все — тогда показывается предупреждение и пустой PDF
   не создается.
4. «Сформировать PDF» → документ сохраняется в `output/` с меткой
   времени и открывается автоматически.

Формат CSV:

```csv
product,price,qty
Чайник,4500,12
Сковорода,3200,18
```

- `product` — название товара (обязательно, не пустое). Читаются
  кодировки UTF-8 (с BOM) и Windows-1251.
- `price` — цена за единицу, число **больше нуля** (разделитель — точка
  или запятая).
- `qty` — количество, **целое** число ≥ 0 (0 — допустимо: товар без
  продаж).

Правила расчетов и оговорки (они печатаются в самом отчете):

- **Выручка = цена × количество.** Прибыль, маржинальность, динамика
  продаж, скидки и возвраты в отчете не рассчитываются и не
  упоминаются как факты: во входном формате их колонок нет.
- Если в файле несколько строк с одинаковым названием (после обрезки
  краевых пробелов — это одно название), они **агрегируются**:
  количества и выручка суммируются; в таблице показывается средняя
  цена (выручка ÷ количество). Правило одинаково применяется к
  таблице, долям, рейтингам и диаграмме.
- **Общая выручка равна нулю**: деление на ноль не выполняется, доли
  показываются недоступными с пояснением; итоги и рейтинги при этом
  рассчитываются честно (нули).
- Рейтинги сортируются по убыванию; при равных значениях — по
  названию товара (воспроизводимый порядок). Таблица товаров —
  в порядке первого появления в файле.
- Некорректные строки не останавливают загрузку: они пропускаются,
  а число пропусков указывается в окне и в самом PDF.
- На диаграмме при большом каталоге показываются топ-10 товаров по
  выручке и полоса «Остальные» со корректной суммой остальных.

## Сценарий «Коммерческое предложение»

Шаги в окне:

1. Нажмите «Выбрать каталог CSV…» (при открытии окна автоматически
   загружается демонстрационный `data/catalogue.csv`). Под путем — число
   товаров и категорий.
2. Отфильтруйте каталог: выпадающий список категорий строится **из данных
   файла** (не зашит в код), плюс поиск по артикулу и названию.
3. Отметьте товары в списке и нажмите «Добавить выбранные →» (количество
   для добавления берется из поля «Количество»). Повторное добавление
   того же товара суммирует количество.
4. В «Составе предложения» можно изменить количество (выделите строку —
   «Применить к выбранным») или убрать позиции. Итоги пересчитываются
   сразу: итог без скидки, скидка (только если указана) и итог к оплате.
5. Скидка: процент от 0 до 90 и **только по явному вводу** — при 0 отдельная
   строка «Скидка 0 %» не показывается ни в окне, ни в PDF.
6. Заполните реквизиты (все необязательные; пустые блоки в PDF не
   выводятся): поставщик, получатель, номер (пусто — сгенерируется
   автоматически, `КП-ГГГГММДД-NNNN`), срок действия, комментарий.
   Кнопка **«Заполнить пример»** подставляет условные реквизиты и
   наполняет состав предложениями **из реально загруженного каталога**
   (демо-SKU, если есть в каталоге; либо первые два товара — чужой
   каталог не подменяется, несуществующие SKU не придумываются) со
   скидкой 10 %; после нажатия все поля можно изменить вручную.
7. «Сформировать коммерческое предложение» → PDF в `output/` с меткой
   времени и автооткрытие. Пустое предложение PDF не создает.

Формат CSV-каталога (обязательные колонки `sku`, `name`, `category`,
`price`, необязательная `description`; кодировки UTF-8 с BOM и
Windows-1251):

```csv
sku,name,category,price,description
IR-001,"Утюг паровой HomePro 2400",Утюги,4590,"Керамическая подошва"
```

Правила:

- SKU непустой и уникальный; название и категория не пустые; цена —
  число больше нуля. Некорректные строки пропускаются с указанием
  причин (число пропусков показывается в окне).
- Повторный SKU с **теми же** данными склеивается в одну карточку; с
  **отличающимися** — ошибка загрузки (предложение не создается, чтобы
  не выбрать случайную версию товара).
- Товары с одинаковыми названиями, но разными SKU — разные товары.
- Формулы: сумма позиции = цена × количество; итог до скидки = Σ сумм;
  скидка = итог × % / 100; итог к оплате = итог до скидки − скидка.
  Расчеты в `Decimal`; округление до копеек только при выводе
  (0,005 → 0,01), поэтому строки итогов не расходятся на копейки.
- Количество позиции — целое ≥ 1; скидка — от 0 до 90 %; суммы всегда
  неотрицательные.

## Ограничения демонстрационных данных

- `data/sales.csv` и `data/catalogue.csv` — **условные примеры**: товары,
  цены и организации придуманы для показа и тестов, реальные
  характеристики товаров и реквизиты компаний не описаны.
- Название демонстрационного каталога помечено как условное в самом
  файле и в шаблоне реквизитов окна предложения.
- Демо-файлы используются только при открытии окон по умолчанию —
  выбранный пользователем файл всегда имеет приоритет.

## Тесты

Бизнес-логика не зависит от Tkinter и покрыта `unittest` — включая
интеграционную генерацию PDF. Из корня репозитория:

```powershell
.\venv\Scripts\python.exe -m unittest discover pdf_studio\tests
```

Пакеты: `test_certificate.py` (сертификат), `test_sales.py` (расчеты
отчета) и `test_quotation.py` (коммерческое предложение). Тесты создают
CSV во временных папках и не перезаписывают ранее созданные документы.

## Возможная ошибка запуска

Если при генерации появляется `OSError: cannot load library
'libgobject-2.0-0.dll'` — дело в системных библиотеках GTK/Pango, а не в
коде. Способ настройки описан в корневом `README.md` (раздел «Важная
особенность WeasyPrint на Windows»).
